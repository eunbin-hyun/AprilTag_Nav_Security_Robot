# 운영 런타임 의존성만. 이 파일이 운영 이미지에 들어간다(backend/Dockerfile).
#
# ⚠ 시험 도구(pytest·pytest-asyncio·pytest-xdist·jsonschema)는 여기 두지 않는다.
#   운영 이미지에 pytest가 들어 있으면 `docker exec c207-backend pytest` 한 줄로 운영 DB
#   스키마가 drop된다. 개발·시험 환경은 requirements-dev.txt를 설치한다.
#
# ⚠ 직접뿐 아니라 간접 의존성까지 전부 `==`로 못박는다. 상한 없는 간접 의존성 하나가
#   새 판을 내면 같은 커밋이 어제는 뜨고 오늘은 죽는다 — 2026-08-05 젠킨스 빌드 #74가
#   그렇게 죽었다. alembic 1.14.0의 선언이 그냥 `Mako`라 판 제한이 통째로 없었고,
#   그날 올라온 Mako 1.4.0이 최상위 `tools` 패키지를 site-packages에 같이 심어
#   backend/tools/를 가렸다. requirements.txt는 한 줄도 안 바뀌었는데 이미지가 바뀌었다.
#   그때까지 판을 붙잡고 있던 것은 선언된 적 없는 도커 레이어 캐시뿐이었다.
#
# 판을 올릴 때는 사람이 여기서 직접 고치고, 고친 뒤 이미지를 한 번 빌드해 확인한다.
# 목록을 새로 뜰 때는 반드시 리눅스 컨테이너 안에서 뜬다 — 윈도우 venv의 `pip freeze`
# 에는 리눅스 전용 uvloop이 아예 없고 대신 윈도우 전용 colorama가 들어간다.
# 그대로 옮기면 운영 이미지에서 uvloop이 조용히 빠지고 uvicorn이 기본 asyncio 루프로
# 떨어진다(에러가 안 나서 아무도 안 알려준다). 그래서 그 둘만 환경 표시를 달아 뒀다.
#
#   docker run --rm -v "$PWD:/w" python:3.12-slim \
#     sh -c "pip install -q -r /w/requirements.txt && pip freeze"

#   설치하기 시작했고, 그것이 우리 `backend/tools/`를 가로채 실서버가 내려갔다(젠킨스 #74).
