## 2. 확정된 모터 배선과 타이머

| 기능 | STM32 핀 | 타이머 | BTS7960 |
|---|---|---|---|
| 정방향 PWM | PA0 | TIM5_CH1, 20kHz | RPWM |
| 역방향 PWM | PA3 | TIM5_CH4, 20kHz | LPWM |
| 정방향 Enable | PE2 | GPIO | R_EN |
| 역방향 Enable | PE3 | GPIO | L_EN |
| 엔코더 A | PB6 | TIM4_CH1 | Encoder A |
| 엔코더 B | PB7 | TIM4_CH2 | Encoder B |

초기에는 역방향 PWM을 PA1/TIM5_CH2에 배정했으나, PA1이 개발보드의 온보드
자이로센서 INT1 출력과 기판상에서 공유되어 역방향 PWM이 정상 전달되지
않았다. 현재 프로젝트와 `.ioc`는 LPWM을 PA3/TIM5_CH4로 사용한다.

## 3. UART 진단 기능

`tools/uart_protocol_test.py`에 다음 명령이 구현되어 있다.

```powershell
py tools\uart_protocol_test.py echo --port COM14 --text STM32
py tools\uart_protocol_test.py motor-test --port COM14 --percent 30 --duration 1000
py tools\uart_protocol_test.py encoder-read --port COM14
py tools\uart_protocol_test.py encoder-monitor --port COM14 --seconds 10
py tools\uart_protocol_test.py encoder-test --port COM14 --percent 30 --duration 1000
py tools\uart_protocol_test.py pid-test --port COM14 --target-mm-s 150 --duration 3000
```

진단 안전 제한:

- Open-loop motor test: `0%` 또는 `-60.0~-20.0%`, `+20.0~+60.0%`
- Motor test duration: `100~10000ms`
- PID test target: `-300~+300mm/s`, 0 제외
- PID test duration: `500~5000ms`
- PID motor output: 최대 절댓값 `40%`
- PID telemetry: ControlTask와 같은 `10ms` 주기
- Motor/PID test 모두 펌웨어 자동 정지
- PC 도구도 시험 종료 시 별도의 정지 명령을 보내 이중 차단

진단 Message ID:

| ID | 이름 |
|---:|---|
| 0xF0 / 0xF1 | DIAG_ECHO request/response |
| 0xF2 / 0xF3 | DIAG_MOTOR_TEST request/response |
| 0xF4 / 0xF5 | DIAG_PID_TEST request/response |

엔코더 진단은 별도 Message ID를 만들지 않고 실제 Jetson에서도 사용할
`TELEMETRY_DRIVE(0x80)`의 `encoder_count`, `measured_speed_mm_s`,
`motor_duty_permille`을 재사용한다.

## 4. 엔코더 및 바퀴 임시 보정값

현재 적용한 값:

```text
counts_per_wheel_revolution = 1600 count/rev
nominal wheel diameter      = 64 mm
wheel circumference         = 201.06 mm = 0.20106 m
encoder direction           = forward positive
```

`1600 count/rev`는 손으로 측정한 대략적인 값이고, 201.06mm는 바퀴 명목
지름으로 계산한 값이다. 바퀴와 차체가 조립되면 여러 회전을 평균 내어 Count를
다시 측정하고, 실제 바닥 이동거리로 유효 구름 둘레를 재보정해야 한다.

엔코더 속도는 10ms 주기로 계산한다. 현재 보정에서 10ms 동안 1 Count는 약
12.6mm/s이므로 텔레메트리 속도가 126, 138, 151mm/s처럼 계단식으로 보이는
것은 정상적인 양자화 현상이다.

## 5. 현재 PID 구성

현재 속도 제어는 PI 제어와 모터 데드존 feed-forward를 사용한다.

```text
Kp = 50
Ki = 5
Kd = 0
minimum running PWM = 22%
maximum PWM = 40%
control period = 10ms
```

모터는 약 20% 이하에서 정지 마찰을 이기지 못했기 때문에 비영점 목표속도에는
22% 기본 출력을 적용하고 PID 출력은 그 주변의 보정값으로 사용한다. 과속
보정이 갑작스러운 역토크를 만들지 않도록 출력은 항상 목표 방향 안에서만
`0~40%`로 제한된다.

생산용 `CMD_DRIVE`의 속도·조향 한계는 아직 0이며 비영점 명령이 의도적으로
차단되어 있다. 현재 PID 시험은 생산 한계를 풀지 않는 시간 제한 진단 경로다.

## 6. 확인된 시험 결과

### 6.1 Open-loop 모터

- 약 10~15%에서는 모터가 회전하지 않음
- 약 20% 이상에서 회전 시작
- PA3 변경 후 정·역방향 모두 정상
- 자동 정지 정상

### 6.2 엔코더

30% / 1초 정방향 시험:

```text
Count delta: +1923
Count delta: +1971
Direction result: MATCH
Automatic stop: VERIFIED
```

정방향에서 Count 증가, 역방향에서 Count 감소를 확인했다.

### 6.3 무부하 PID (Ki=0 기준 결과)

목표 `+150mm/s`, 3초:

```text
average measured speed = +138.2mm/s
average tracking error = +11.8mm/s
peak reported PWM      = 23.2%
encoder delta           = +3235
automatic stop          = verified
```

목표 `-150mm/s`, 3초:

```text
average measured speed = -139.8mm/s
average tracking error = -10.2mm/s
peak reported PWM      = 23.2%
encoder delta           = -3253
automatic stop          = verified
```

정·역방향 부호와 출력은 대칭적이며 폐루프 경로가 정상 동작한다.

### 6.4 외란 시험

무부하에서 부하를 가했을 때:

```text
speed: 약 138 -> 0~50mm/s
PWM:   약 22.6 -> 최대 29.5%
```

속도 저하에 따라 PWM이 증가했으므로 피드백 방향은 정상이다. 그러나 지속
부하에서 목표속도 150mm/s를 복구하지 못했으므로 현재 외란 억제 성능은
부족하다.

부하를 제거했을 때:

```text
speed: 50 -> 113 -> 126~138mm/s
PWM:   27.0 -> 23.8 -> 22.6%
```

부하 해제 후 원래 무부하 속도와 PWM으로 복귀했다.

이 결과는 `Ki=0`인 P 제어 기준 결과다. 현재는 `Ki=5`를 적용했으므로 같은
조건에서 목표/측정 휠 RPM, PWM, 정상상태 오차를 다시 기록해야 한다.

## 7. 다음 작업

1. 현재 보정값 `1600 count/rev`, `201.06mm/rev`로 PI 기준 시험
2. 손 대신 반복 가능한 고정 마찰 장치 또는 실제 차량 하중으로 외란 시험
3. 목표속도 100/150/200/250mm/s 단계 응답 기록
4. 상승시간, 오버슈트, 정착시간, 정상상태 오차 비교
5. 차량 조립 후 최소 구동 PWM과 실제 구름 둘레 재확인
6. 배터리 전압 변화와 추가 적재 상태에서 재시험
7. 최종 차량 속도·조향 한계를 측정한 뒤 생산용 `CMD_DRIVE` 잠금 해제
8. Stall, 엔코더 단선, UART Timeout 등 Fault 시험 추가

현재 판정은 다음과 같다.

> 엔코더 피드백과 시간 제한 PID 제어 경로는 무부하 벤치에서 정상 동작한다.
> 외란에 대한 PWM 보상도 확인했지만, 지속 부하에서 목표속도를 유지하지
> 못했으므로 실차 PID 튜닝과 안전 검증은 아직 완료되지 않았다.
